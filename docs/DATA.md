# 输入数据合同与发布范围

## ROOT 数据

`kr.root` 与 `2615.root` 都应包含 TTree `out_tree`。以下字段必须是等长的一维数值数组，值有限；两路信号应为正。采集选择、变量定义和单位必须与原研究一致，仅字段同名不代表数据可互换。

| 字段 | 含义与用途 |
|---|---|
| `qS1_PCs` | 已有修正后的 S1 |
| `qS2Bdes_PCs` | 已有修正后的底部 S2 |
| `dt` | 漂移时间，保持原始数值单位 |
| `wS2CDF_max` | S2 宽度 |
| `xS2max_desImageMCPAF_firstS2` | 事件重建 x 位置 |
| `yS2max_desImageMCPAF_firstS2` | 事件重建 y 位置 |
| `runNumber` | 整数 run 标识，不能作为回归特征 |

调查脚本另外读取 Kr 的 `qS1_nn_factor`、`qS2_nn_factor`。默认运行入口执行时间匹配与重采样，不要求这两个额外字段。

### 原研究固定配对

- P1：Kr 9568 → 2615 keV 9563/9566。
- P2：Kr 9685/9695 → 2615 keV 9698。

新增的运行入口会拒绝缺少配对 run 或含未映射高能 run 的输入，避免历史脚本在未覆盖事件上保持原能量却仍生成整体结果。新数据必须先根据真实时间关系重新设计配对和验证，不能只修改 run 标签来绕过检查。

原研究两份数据分别含 787,039 和 19,036 个事件。检查器要求每个实际使用的 Kr run 至少有 100 个峰窗事件用于归一化，每个合并时段至少有 2,000 个峰窗事件用于局部分箱。这些只是减少直接运行失败的工程门槛，不是科学充分性判据，也不保证所有候选拟合成功。

## 公开内容

主目录包含原研究脚本、汇总结果、关键图、解释文档和人工数据生成代码。`results/provenance.json` 记录所保留原始代码与证据的来源提交、来源路径及 SHA-256。

原始 ROOT、逐事件实验数据、二进制模型、内部服务器脚本、账号信息与本地运行环境不发布。演示和真实复现都写入被 Git 忽略的 `local_results/`；请勿手动将真实数据加入版本库。

完整旧版公开材料仍保留在[历史归档](../history/README.md)。它同样不含原始实验数据。
